# 2026-08-17 — Corpus refresh (qa_corpus_20260817) + kp-docs/markdown rebuild

## Source dump file

New Postgres database `qa_corpus_20260817` was loaded locally from a
read-only snapshot of the live **qa** environment's RDS, produced via
`scripts/with-remote-env.sh qa` (see
`new_docs_aug2026/corpus-exports_20260817/README.md`). It contains **only**
`documents` + `document_relations` (restored from `qa-doc-metadata.sql`, a
`pg_dump --no-owner --no-acl`) — it does **not** include `document_texts`
(no full/OCR'd text at all, table doesn't exist in this db). Full text for
the current corpus lives only in the live QA RDS's `document_texts` table;
this machine has no AWS CLI/credentials configured to pull it, and no
`MISTRAL_API_KEY` to OCR locally.

The human-readable listing `new_docs_aug2026/corpus-exports_20260817/qa-corpus-docs.txt`
was copied as-is to `eval-generation-notes/documents-list_20260817.txt`
(supersedes `documents-list-207_20260807.txt`, which is left in place,
untouched, as historical reference).

## Metadata schema notes

`qa-corpus-docs.txt` / `documents-list_20260817.txt` is a **superset** of the
old format:
- **Additive fields** (new, fine): `status`, `translation_of`,
  `has_translations`. These are genuinely new info, not present in
  `documents-list-207_20260807.txt` at all.
- **No fields were dropped from the underlying corpus** — `documents.doi`
  and `documents.publication_title` still exist and are populated in
  `qa_corpus_20260817` for most docs (117/206 have a `doi`, 151/206 have a
  `publication_title`), same as before. Neither field was ever part of the
  `documents-list-*.txt` listing format (old or new) — that's a listing-format
  choice, not a data loss.
- **The one place `doi`/`publication_title` are genuinely absent**: the new
  placeholder stub for `2026_fortaleciendo-sinergias-electromovilidad-calidad-aire_XXXX`
  (see below) — this specific document has no `doi` and no
  `publication_title` value in the source data, so its frontmatter omits
  both fields entirely (not an extraction artifact, just blank source data
  for this one doc).

## kp-docs/markdown/ rebuild

Old `kp-docs/markdown/` (195 files, all pre-dating today) was archived
wholesale to `kp-docs/markdown_bkup0804/`, untouched. A fresh
`kp-docs/markdown/` was then built to represent **only** the current
206-doc corpus, **excluding withdrawn documents**:

- **188 files** carried forward unchanged from the archive (already
  matched the new corpus's searchable docs, same `external_id`, no
  content change needed).
- **12 files** newly generated by a new script,
  `scripts/db_text_to_markdown_s3_docs.py` (companion to
  `scripts/db_text_to_markdown.py`), which covers `document_texts` rows
  already sitting in local Postgres (`parse_backend='mistral'`) whose
  source PDF lives in S3/MinIO (`s3_key: documents/*.pdf`) rather than
  under `kp-docs/CN-KPs-PDF/` or `kp-docs/ES-KPs-PDF/` — the original
  script only ever scans those two local folders, so it silently never
  covered these 12 despite the text already being available. No new OCR
  was run; this is purely surfacing text that already existed.
- **1 file** is a metadata-only placeholder (see below).
- **5 files** (withdrawn docs) moved out to `kp-docs/markdown-withdrawn/`,
  not included in the live `markdown/` dir:
  `2017_global-review-of-finance-for-sustainable-urban_8290`,
  `2018_resilient-and-affordable-housing-for-all-lessons_6969`,
  `2020_the-economic-case-for-greening-the-global_5627`,
  `2022_toward-credible-transport-carbon-dioxide_5852`,
  `2023_electric-school-bus-us-market-study-and-buyers_5598`.
- **2 files** (orphaned — no longer in the corpus at all, not withdrawn,
  just gone/renamed) were **not** carried forward into the new
  `kp-docs/markdown/`; they remain only in `kp-docs/markdown_bkup0804/`:
  `2021_mexico-frontrunners-creating-safe-affordable-and_6429` (duplicate),
  `2025_technical-note-for-a-dataset-of-electric-school_9675` (renamed to
  `26_tech_esb-adoption_version-10`, which DOES have a fresh file in the
  new `markdown/`).

Final state: `kp-docs/markdown/` = **201 files** (= 206 total − 5 withdrawn,
confirmed exact match against the corpus's searchable `external_id` set).
`kp-docs/markdown-withdrawn/` = 5 files. `kp-docs/markdown_bkup0804/` = 195
files (unchanged snapshot of the pre-refresh state).
